# 업무 캘린더

폰과 개인 노트북에서 같이 쓰는 업무 캘린더 + 체크리스트 앱 (PWA).
일정은 기기에서 종단간 암호화한 뒤 동기화된다.

## 기능

- **오늘 할 일** (열면 바로 보이는 화면): 오늘 일정, 완료 수, 밀린 업무, 진행률, 다가오는 7일
- **주간 / 월별**: 날짜별 일정과 완료 현황, 날짜를 눌러 바로 추가
- **업무 체크리스트 + 준비물 체크리스트**: 모두 체크하면 자동 완료
- **반복 업무 템플릿**: 예) "입찰"을 고르면 업무 단계와 준비 서류가 자동으로 채워짐
- **반복 일정**: 매주 / 매월 N회
- **기기 간 동기화**: 종단간 암호화 (아래 참고)
- **오프라인 동작**, 홈 화면에 설치 가능, 백업 내보내기 / 가져오기

## 설치 (처음 한 번)

### 1. Supabase 만들기 (무료)

1. https://supabase.com 가입 → New project (Region: Northeast Asia (Seoul) 권장)
2. 왼쪽 **SQL Editor** → `supabase.sql` 내용을 붙여 넣고 **Run**
3. **Project Settings → API**에서 *Project URL*과 공개 키(*anon* 또는 *publishable*)를 복사
   - `service_role` / `secret` 키는 절대 쓰지 말 것

### 2. 배포 (GitHub Pages)

이 저장소 → **Settings → Pages** → Source: **Deploy from a branch**, Branch: **main** / **(root)** → Save.
1~2분 뒤 `https://jayfwng.github.io/work_calendar/` 에서 열린다.

저장소에는 앱 코드만 있고 일정 데이터는 올라가지 않는다.
`config.js`는 비워 두고 Supabase URL·공개 키는 각 기기 앱 설정 화면에서 입력한다.

### 3. 기기 연결

1. **노트북**: `https://jayfwng.github.io/work_calendar/` 열기 → 설정 → 기기 간 동기화 → **새로 시작** → 동기화 키(25자) 확인
2. **폰**: 같은 주소 열기 → 공유 버튼 → **홈 화면에 추가** (안드로이드는 메뉴 → 앱 설치)
3. 폰 앱 → 설정 → **키로 연결**에 노트북의 키 입력

이후엔 수정할 때마다, 앱을 열 때마다, 열려 있는 동안 1분마다 자동으로 동기화된다.

> 예전에 `index.html` 파일을 직접 열어 쓰던 데이터는 주소가 달라서 자동으로 넘어오지 않는다.
> 예전 화면에서 **백업 내보내기** → 새 주소에서 **백업 가져오기**.

## 컴퓨터 화면

가로 1024px 이상에서는 자동으로 3단 화면이 된다.

- 왼쪽 메뉴: 화면 이동, 새 일정, 템플릿으로 바로 추가. `[` 또는 ☰로 접기/펼치기 (기기마다 기억)
- 가운데: 큰 달력. **날짜 더블클릭 → 빠른 추가**(`14:00 미팅`, `오후 2시 반 회의`처럼 앞에 시간), **일정 더블클릭 → 수정**
- 오른쪽: 오늘 할 일. 끌어서 놓거나 ▲▼로 우선순위 변경 (폰에도 같은 순서로 동기화)

### 키보드 단축키 (`?`로 보기)

| 키 | 동작 | 키 | 동작 |
|---|---|---|---|
| `1` `2` `3` `4` | 월별·주간·오늘·설정 | `N` | 새 일정 |
| `M` `W` `T` | 월별·주간·오늘 (한 번 더 = 지금 날짜) | `P` | 템플릿 골라서 새 일정 |
| `←` `→` | 이전/다음 주·달 | `Ctrl`+`Enter` / `Ctrl`+`S` | 편집 창 저장 |
| `[` | 왼쪽 메뉴 접기 | `Esc` | 닫기 |
| `R` | 지금 동기화 | `?` | 단축키 도움말 |

한글 입력 상태에서도 동작한다.

## Windows 프로그램

Release의 `work-calendar-setup-1.1.N.exe`를 받아 실행한다 (관리자 권한 불필요, 내 계정에만 설치).
서명 안 된 프로그램이라 "Windows의 PC 보호" 창이 뜨면 **추가 정보 → 실행**.

- 웹 앱과 같은 화면 (3단 컴퓨터 화면, 단축키, 동기화 모두 동일)
- **바탕화면에 고정**: 테두리 없이 다른 창들 뒤, 바탕화면 위에 늘 떠 있는 모드.
  창 위치·크기를 먼저 맞춘 뒤 설정 또는 트레이 메뉴에서 켠다. `Win+D`(바탕화면 보기)를 누르면 잠깐 같이 숨는다.
- **트레이 아이콘**: 열기 / 바탕화면에 고정 / Windows 시작 시 실행 / 종료
- 창을 닫으면 트레이로 숨는다. 완전히 끄려면 트레이 아이콘 우클릭 → 종료
- 창 위치·크기 기억, 두 번 실행해도 창 하나만
- 업데이트: 새 설치 파일을 받아 그대로 실행 (데이터 유지)
- 데이터는 `%LOCALAPPDATA%\io.github.jayfwng.workcalendar` 아래 (브라우저와 별도, 동기화로 맞춤)

## 안드로이드 앱 (APK)

`main`에 코드가 올라가면 GitHub Actions가 서명된 APK와 Windows 설치 파일을 만들어 같은 **Release**에 올린다.

- 설치: 폰에서 저장소 → Releases → 최신 버전의 `work-calendar-1.1.N.apk` 받기 → 열기
  ("출처를 알 수 없는 앱" 허용은 설치 후 다시 끄기)
- 업데이트: 새 버전 APK를 받아서 그대로 설치 (데이터 유지)
- 권한: 인터넷만 사용. 안드로이드 클라우드 백업·기기 이전에서 앱 데이터 제외
- 서명 키는 저장소에 없고 Settings → Secrets and variables → Actions 의
  `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD` 에만 있다. **키 파일은 따로 안전하게 보관할 것**
  (잃어버리면 기존 앱 위에 업데이트가 안 되고, 지우고 새로 설치해야 함 — 동기화돼 있으면 데이터는 복구됨)
- Release 노트의 "서명 인증서 SHA-256"이 매 버전 같아야 정상

로컬 빌드: `npm ci && npm run sync:android` 후 `android/`를 Android Studio로 열기.

## 암호화 방식

- 동기화 키: 기기에서 만든 25자 난수(약 125비트). **서버로 보내지 않는다.**
- 키에서 HKDF-SHA256으로 ① AES-256-GCM 암호화 키 ② 저장소 ID를 만든다.
- 서버(Supabase)에는 `저장소 ID / 암호문 / 버전`만 저장되어 서버 운영자도 내용을 볼 수 없다.
- 테이블은 직접 읽거나 목록을 볼 수 없고, 저장소 ID를 아는 경우에만 함수로 읽고 쓸 수 있다.
- 키를 잃어버리면 서버 데이터는 복구할 수 없다(각 기기 데이터는 남아 있음).
- 두 기기에서 따로 고쳐도 일정 단위로 병합된다(나중에 수정한 쪽 우선, 삭제도 반영).

## 주의

- **개인 기기(폰, 개인 노트북) 전용으로 쓰기.** 회사 PC에서는 동기화를 켜지 않는다.
- 암호화와 별개로, 업무 내용을 개인 기기에 적는 것도 회사 정책이 있을 수 있으니
  입찰가나 내부 기밀 수준의 정보는 넣지 않는 걸 권장.
